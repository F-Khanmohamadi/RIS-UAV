# Joint RIS Placement and UAV Mission Planning for Energy-Efficient Logistics-Assisted Cellular Offloading


## 1. Methods

All four methods use the same planner. They differ only in how the RIS sites are chosen.

| Method (paper) | Key | RIS sites | Planner |
|---|---|---|---|
| **Route-aware RIS (proposed)** | `proposed` | chosen jointly with the hovering points and the grouping (a cell may also be served without RIS) | trained attention policy (greedy decoding) → repair → iterative local search (100 iterations, full multi-RIS model) → TSP ordering (LKH) |
| Coverage-based RIS | `coverage` | maximize the reliable hovering coverage $\sum_i \lvert\mathcal N_i(\mathbf r)\rvert/\lvert\mathcal Q_i\rvert$ under the multi-RIS model (coordinate ascent from the largest-coverage site of each cell, at most two passes) | same planner, sites fixed |
| Random RIS | `random` | one site per cell, drawn uniformly from the candidates with at least one reliable hovering point | same planner, sites fixed |
| No RIS | `none` | none (direct links only) | same planner |

Implementation: `risuav/sim/eval_rx.py` (methods and evaluation), `risuav/sim/plan_mr.py` (decoding, repair, local
search, TSP), `risuav/sim/model_rx.py` (policy), `risuav/sim/train_rx.py` (training).

## 2. Main results

Final evaluation: 120 test missions per platform on two unseen city layouts, three training seeds (360 mission–seed
pairs per method). All plans are feasible. Mean UAV energy (kJ):

| Method | Facade RIS | Ground-mobile RIS |
|---|---|---|
| No RIS | 101.06 | 101.32 |
| Random RIS | 97.35 | 96.44 |
| Coverage-based RIS | 95.11 | 94.68 |
| **Proposed** | **90.72** | **90.14** |

The proposed method saves 10.2% (Facade) and 11.0% (Ground-mobile) compared with No RIS, with lower energy in every
mission, and 4.6% and 4.8% compared with Coverage-based RIS (lower energy in 93.1% and 94.2% of the mission–seed
pairs). These values are regenerated by `python -m risuav figures` (Section 4) from the files in `artifacts/`.

## 4. Installation

Requirements: Python **3.13** (64-bit), 8 GB RAM, about 1 GB of disk for the quick test and 3 GB for the service
tables of the full study. Windows, Linux and macOS are supported. A GPU is optional (training only).

```bash
python3.13 -m venv .venv
source .venv/bin/activate                    # Windows: .venv\Scripts\activate
python -m pip install --upgrade pip
pip install -r requirements.txt
python -m risuav check                       # every package must show "ok"
```

GPU training: install the CUDA build of `torch==2.15.0` from [pytorch.org](https://pytorch.org/get-started/locally/)
before `requirements.txt`. Only the policy network runs on the GPU; GPU runs are reproducible on the same GPU but
not bit-identical to CPU runs. The published checkpoints were trained on the CPU.

VS Code: open the folder, select the `.venv` interpreter, and use the entries of the *Run and Debug* panel, which
call the same commands.
